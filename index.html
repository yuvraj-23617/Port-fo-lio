04CASE STUDY · 01

/ DISTRIBUTED CODING ASSESSMENT PLATFORM — SPRING BOOT · RABBITMQ · DOCKER

Running untrusted code at scale.

3LANG

ROLE — DESIGN + FULL-STACK IMPLEMENTATION
STACK — SPRING BOOT · RABBITMQ · DOCKER · POSTGRESQL
RESULT — ASYNC JUDGE FOR PYTHON, JAVA & C++

01 / PROBLEM

Synchronous judging doesn't scale.

Traditional coding platforms run submissions inline — the request thread blocks while the compiler runs and test cases execute. Under any real load that means queue buildup, timeouts, and broken UX. And the moment you're executing code someone else wrote, you're already in security territory.

02 / APPROACH

Decouple submission from execution.

The submission endpoint only validates and enqueues. Workers pull from RabbitMQ, spin up an isolated Docker container per submission, run the tests, and push results back. Spring Boot handles the API; PostgreSQL stores users, problems, and submissions with proper indexing on the fields the dashboard actually queries.

03 / DECISION

Sandbox everything, trust nothing.

Every submission runs in a fresh, resource-capped container with no network, a read-only filesystem, and a hard timeout. It costs latency, but you cannot run arbitrary user code on the same machine that holds your database. This was the design decision I'd defend hardest in review — the trade-off is deliberate.

04 / OUTCOME

Async, multi-language, and instructor-friendly.

Three languages supported (Python, Java, C++), submissions returned asynchronously with live status, and an admin dashboard that lets non-technical instructors manage problems without engineering help. The candidate UI is a real terminal — because the assessment should feel like the tools engineers actually use.

05 / NEXT

What I'd carry forward.

Move to Kubernetes for per-job pod isolation and horizontal worker scaling. Add structured tracing across the queue so a slow submission can be followed end-to-end. And harden the sandbox further with seccomp profiles — the security model is never done.

"The hard part isn't running code — it's running untrusted code safely."

05CASE STUDY · 02

/ E-SUMMIT'26 — IIIT-DELHI'S FLAGSHIP ENTREPRENEURSHIP SUMMIT

The 5× plan, executed.

0×

ROLE — HEAD OF SPONSORSHIP DOMAIN
WINDOW — OCT 2025 → MAR 2026
RESULT — HIGHEST REVENUE IN EVENT HISTORY

01 / PROBLEM

Flat revenue, rising target.

E-Summit had grown every year, but the sponsorship number hadn't kept pace. The outreach playbook — cold emails, one static deck, one point of contact, no follow-up system — was producing flat results against a rising target. The ask was the same for every company, so the answer was too.

02 / THE BET

Stop fundraising. Start selling.

The reframe that carried the whole plan: sponsorship isn't a donation drive, it's a sales pipeline. Every lead gets an owner, a stage, and a next action with a date on it. Once we tracked it like a pipeline, the leaks became obvious — most deals weren't lost on price, they were lost on silence after the second email.

03 / THE PLAYBOOK

Five moves that compounded.

  • 01Tiered packages. Replaced one generic ask with three defined tiers — so a company could say yes at a size that fit its budget instead of saying no to the only number we offered.
  • 02Ownership per lead. Every prospect had exactly one person accountable for it. No shared inboxes, no "I thought you were following up."
  • 03Proof, not promises. Rebuilt the deck around past footfall, past sponsor logos, and last year's actual numbers. We sold evidence, not adjectives.
  • 04A follow-up cadence. Three touches over three weeks, scripted, tracked in one sheet. Consistent follow-through beat clever copywriting every single time.
  • 05Close with a deadline. Real cut-offs for logo placement and deliverables — a reason to decide now rather than a reason to "circle back".
04 / EXECUTION

Same team, different shape of work.

I rebuilt the pipeline end-to-end: how leads were sourced, how the pitch was sequenced, and how follow-through was tracked. Coordinated across sponsorship, marketing, and operations so the story stayed consistent from first contact to signed agreement — and reviewed the sheet with the team weekly instead of at the end.

05 / OUTCOME

Record revenue, closed.

The vertical closed the highest sponsorship revenue in E-Summit's history — a 5× increase over the previous edition. The number matters less than the method: the playbook is now documented and handed over as a repeatable system, not a one-off result.

"Same team, same event — different shape of work."
